# 스루오더 (ThruOrder) — Pleos Connect 차량 앱 v0.5

> ※ 공모전 시연용 데모입니다. 앱에 표시되는 매장명(스타벅스·맥도날드 DT 매장)은 시연용 예시이며 해당 브랜드와 제휴·승인 관계가 없습니다. 로고는 사용하지 않았고, 메뉴명은 일반명으로 표기했으며 가격·준비시간은 가정값입니다.

도착하는 순간, 갓 나온 한 입. 차의 도착 시간에 맞춰 매장 조리 시작을 권고하는 Pleos 드라이브스루 앱입니다.

## 기능 한눈에 보기

| 단계 | 화면 | 하는 일 | 쓰는 Pleos/Android API |
|---|---|---|---|
| 0. 연결 | 권한 안내 카드 | 왜 필요한지 한 줄 설명 후 내비 권한 요청 | `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH` 런타임 권한 |
| 1. 매장 고르기 | 홈 | 내비에 목적지가 있으면 **가는 길 DT**(앞으로 30분 안에 닿고 들러도 8분 이내, "+N분". 목적지까지 45분 이하인 짧은 길이면 길 전체), 없으면 **반경 15km DT**. 카페/버거 필터 | `getRouteStateInfo`, `getDestinationInfo`, `getCurrentLocationInfo`, `requestTrip` |
| 2. 같이 고르기 | 메뉴판 | 카테고리 탭, + 버튼으로 담기. "같이 고르기" → 큰 QR → 뒷좌석 폰에서 담으면 차 장바구니에 바로 합쳐짐 | — (웹 메뉴판 + 중계 서버) |
| 3. 주문 | 하단 장바구니 바 | 누가 무엇을 담았는지 펼쳐 보기 → 주문하기 | 경로 안내 중 `addWaypoint`, 아니면 `requestRoute` |
| 4. 기다리기 | 주문 상태 | 도착 시각 크게, 주문 → 조리 대기 → 조리 중 → 완성 단계 표시, 주문코드, "내비 경로에 매장을 넣었어요" 확인 | `onWaypointChanged`·`onWayPointInfo`·`onDrivingInfo`(남은 시간) |
| 5. 주행 중 | 주행 화면 | 매장 · 도착 시각 · 조리 단계 3줄만, 버튼 없음 | `CarUxRestrictions`, 기어 상태, `distractionOptimized` |
| 6. 픽업 | 주문 상태 | "받았어요" → 경유지 정리 | `removeWaypoint` / `cancelRoute` |

Fresh Timing: 도착 예정 − (주문 내 가장 오래 걸리는 메뉴 준비 시간 + 픽업 버퍼) = 권장 조리 시작. 도착이 바뀌면 조리 전까지 다시 계산하고, 조리가 시작되면 고정합니다.

## 화면 원칙 (v0.5 개편)
- Pleos Connect 디자인 가이드가 대전제: 타이포 토큰(Headline 60/56/48 · Title 40/36/32 · Body 30/28/26), 48dp 아이콘, 라이트/다크, 주행 중 3줄 이하·버튼 없음
- 배달의민족처럼: 큰 썸네일 카드 목록, 가로 칩 필터·카테고리 탭, + 하나로 담기, 하단 고정 장바구니 바, 단계형 주문 현황
- 쿠팡플레이처럼: 어두운 바탕 + 큰 제목, 설명 문장 대신 숫자·배지
- 브랜드 컬러 하나(스루오더 블루 #2F6BFF), 빨강은 품절·지연 경고에만. 앱 아이콘도 같은 색
- 사진·로고 대신 이모지 썸네일 (상표 사용 회피)

## 내비 연결이 안 될 때 (모의 모드 / 권한 필요)
NaviHelper SDK는 모든 호출 전에 권한을 확인하고, 없으면 호출을 거절합니다. v0.4까지는 권한을 요청하지 않아 위치·경로·경유지가 모두 비어 있었습니다(모의 값으로 대체).
1. 앱을 켜면 "내비와 연결할게요" 카드 → **허용하기**
2. 허용 창이 뜨지 않거나 상단이 계속 "내비 권한 필요"이면 Android Studio 하단 **Terminal**에서:
   ```
   adb shell pm grant ai.thruorder.app pleos.car.permission.NAVI_ROUTE
   adb shell pm grant ai.thruorder.app pleos.car.permission.NAVI_ROUTE_SEARCH
   ```
   그래도 안 되면 앱을 지웠다가(`adb uninstall ai.thruorder.app`) 다시 Run
3. 상단 **시연** → 패널 아래 진단 줄에서 `내비: 연결됨`, `위치: … (내비)`가 보이면 정상
4. 지도·경로·경유지는 Pleos 기본 내비 앱 화면에서 확인합니다 (Connect-S 기본 1:1 화면이면 왼쪽 내비, 오른쪽 스루오더). 스루오더 안의 지도는 그리지 않습니다 — 지도 화면 API(`NAVI_CUSTOM_MAP`)는 개인 계정에 열려 있지 않습니다

### 앱 아이콘이 두 개 보이면
예전 빌드(기본 안드로이드 아이콘)와 새 빌드가 함께 설치된 경우입니다. 에뮬레이터에서 길게 눌러 지우거나 `adb uninstall ai.thruorder.app` 후 다시 Run 하세요.

## 버전 기록

### v0.4 추가: 내비 경로 위 DT 추천 + 경유지 추가
스루오더를 켰을 때 내비 상태에 따라 추천 방식이 바뀝니다.

| 내비 상태 | 추천 방식 | 주문하면 |
|---|---|---|
| 목적지 없음 | 현재 위치 **반경 15km** DT 매장, 도착 시간순 | 매장을 **목적지**로 설정 |
| 목적지로 경로 안내 중 | 목적지 **가는 길에서 8분 이내로 들를 수 있는** DT 매장, 추가 시간이 적은 순. 카드마다 "경로에서 +N분" 표시 | 매장을 **경유지**로 추가 (원래 목적지는 그대로) |
| 경로 안내 중인데 경로 주변 DT 없음 | 반경 15km 목록으로 대신 표시하고 안내 문구 표시 | 경유지로 추가 |

- 목적지·남은 시간은 NaviHelper `getRouteStateInfo`(경로 안내 여부)·`getDestinationInfo`(목적지 좌표·남은 시간)로 받습니다. 5초마다 확인해 내비에서 목적지를 새로 잡으면 목록이 바로 바뀝니다
- NaviHelper는 경로 좌표(폴리라인)를 주지 않아서, "현재 위치 → 매장 → 목적지"가 "현재 위치 → 목적지"보다 얼마나 늘어나는지를 직선거리로 추정합니다(도로 계수 1.4, 25km/h). 실제 서비스에서는 서버의 경로 API로 계산합니다
- 매장까지 도착 시간은 Pleos `requestTrip`(실제 내비 계산)으로 받습니다
- **시연 바 "목적지" 버튼**: 목적지 없음 → 잠실 롯데월드타워 → 광교 호수공원 → 강남역 → 없음 순으로 바뀝니다. Pleos 내비가 연결돼 있으면 내비에도 실제로 목적지가 설정됩니다
  - 잠실: 강남세곡·송파나루역·송파방이(스타벅스), 송파잠실·가락(맥도날드) 등
  - 광교: 서판교·용인수지(맥도날드), 분당궁내·수지성복(스타벅스)
  - 강남역: 양재SK(맥도날드)

### v0.4 변경: 시연 출발지 = Pleos 에뮬레이터 기본 위치
Pleos 에뮬레이터를 켜면 내비 현재 위치가 **성남시 수정구 시흥동(판교 제2테크노밸리)**으로 잡힙니다(Pleos 개발 문서 예시 좌표 37.4128, 127.0948과 같은 곳). v0.4부터 이 위치를 시연 출발지로 써서 **심사위원이 위치를 따로 설정하지 않아도** 실제 내비 위치와 앱 목록이 일치합니다.
- 기본 매장: 출발지 반경 15km 안의 실제 DT 매장 15곳 (스타벅스 8, 맥도날드 7). 매장명·주소·좌표는 각 브랜드 공식 홈페이지 '매장 찾기' 화면의 공개 정보(2026-11-07 확인)
- 내비 위치가 출발지에서 멀어 주변에 매장이 없으면(예: 해외 좌표) 판교 제2테크노밸리로 자동 전환

### v0.3 추가: QR 동승자 공동 장바구니
1. 매장을 고르면 메뉴판 위에 **큰 QR**이 뜹니다 (‘QR 크게 보기’로 화면 가득 표시, 정차 중에만)
2. 뒷좌석 동승자가 폰 카메라로 찍으면 폰에서 **웹 메뉴판**이 열립니다 (`docs/index.html`, GitHub Pages)
3. 폰에서 ‘누가 고르나요?’(뒷좌석 왼쪽·오른쪽·동승석)를 고르고 메뉴를 담아 **차에 담기**를 누르면 차량 장바구니에 바로 들어옵니다
4. 차량 장바구니 현황과 주문 완료(주문코드·도착 예정)도 폰 메뉴판에 함께 표시됩니다

- 폰과 차량 사이 메시지는 데모용 공개 중계 서버 **ntfy.sh**를 거칩니다 (키·가입 불필요). 매장마다 무작위 10자리 세션을 만들고, 메시지에는 메뉴 ID·수량·좌석 별칭만 담습니다
- 실제 서비스에서는 스루오더 주문 서버가 이 역할을 맡습니다

## 데모 버전의 한계와 실제 서비스 동작

이 저장소는 공모전 시연용 데모입니다. 실제 서비스와 다른 점은 아래와 같습니다.

| 항목 | 데모(이 저장소) | 실제 서비스 |
|---|---|---|
| 현재 위치 | Pleos 내비 위치 사용. 에뮬레이터 기본 위치(판교 제2테크노밸리) 주변 매장만 내장되어 있어, 내비 위치가 그 밖이면 판교로 고정 | 차량 내비 위치를 실시간으로 사용 |
| 주변 DT 매장 탐색 | 판교 반경 15km DT 매장 15곳 내장(공식 홈페이지 공개 정보) | 현재 위치 반경 15km 내 DT 매장을 서버에서 모두 탐색, 이동할 때마다 목록 갱신 |
| 경로 위 DT 판단 | 현재 위치·목적지 좌표로 추가 시간을 직선거리 추정 | 서버 경로 API로 실제 경로 기준 이탈 시간 계산 |
| 브랜드 | 스타벅스·맥도날드만 표기 | 제휴 드라이브스루 매장 전체 |
| 메뉴·가격·준비시간·품절 | 브랜드 공통 모의 데이터 | 매장 POS·주문 시스템과 연동 |
| 결제 | 모의 결제 | 주문 확정 시 결제 승인(차량 결제 등) → 조리 시작 시 확정, 조리 시작 전까지 무료 취소 |
| 매장 전달 | 차량 화면에서 권장 조리 시작만 계산 | 파일럿은 매장 태블릿 웹(Fresh Queue), 프랜차이즈는 주문 API 제휴 |
| 동승자 공동 장바구니(QR 웹) | 포함. 공개 중계 서버(ntfy.sh)로 폰↔차량 동기화 | 스루오더 주문 서버로 동기화, 세션 인증 |
| 매장용 조리 화면(Fresh Queue) | 미포함 (권장 조리 시작은 차량 화면에서 계산·표시) | 매장 웹 화면으로 전달, 직원이 시작·완료 확인 |
| 정체·주행 전환 | 상단 "시연" 패널로 재현 가능 | 내비 남은 시간·차량 주행 상태로 자동 |
| 음성 안내 | 미포함 (Pleos TTS SDK 공개 후 선택 기능) | 조리 지연·도착 직전 짧은 안내 |

카카오 로컬 API 키를 `local.properties`에 넣으면(아래 '선택' 항목) 데모에서도 현재 위치 반경 15km 내 DT 매장 검색을 확인할 수 있습니다.

### (선택) 카카오 REST API 키 설정 — 어느 위치에서든 주변 15km DT 매장을 검색하고 싶을 때

2. 만든 앱 → **앱 키**의 **REST API 키** 복사
3. 앱 설정에서 **카카오맵(로컬 API) 사용 설정**이 꺼져 있으면 켜기 (403 오류가 나면 이 항목 확인)

   ```
   kakao.rest.key=복사한_REST_API_키
   ```
   `local.properties`는 .gitignore에 있어 GitHub에 올라가지 않습니다.

## 실제 연동 / 모의 구분
| 기능 | 연동 | Pleos 미연결 시 |
|---|---|---|
| 현재 위치 | NaviHelper `getCurrentLocationInfo` | 판교 제2테크노밸리(37.4128, 127.0948) |
| 경로 안내·목적지 | NaviHelper `getRouteStateInfo`·`getDestinationInfo` | 시연 바 "목적지" 버튼 |
| 매장별 도착 시간 | NaviHelper `requestTrip` → `onTripInfo.eta` | 직선거리 × 1.4 ÷ 22km/h |
| 주문 매장 남은 시간 | `addWaypoint`/`requestRoute` → `onDrivingInfo`·`onWayPointInfo.remainTime` | 주문 시점 모의 도착 시간 |
| 정차/주행 | Android Automotive `CarUxRestrictions` + 기어(`GEAR_SELECTION`) | 시연 바 스위치 |
| 주변 DT 매장(이름·주소·전화·좌표) | (선택) 카카오 로컬 키워드 검색 (반경 15km) | 판교 인근 DT 15곳 (`MockData.kt`) |
| 메뉴·가격·준비시간 | 모의 데이터 (`MockData.kt`, ThruOrder_mock_data.xlsx와 동일) | — |

상단 배지: **내비 연결**(파란 점) = 실제 SDK 값 / **내비 권한 필요**(빨간 점) = 권한 허용 필요 / **모의 모드** = 내비 없음, 대체 값 사용.

## 실행 방법 (Windows, Android Studio)
1. 압축을 풀고 Android Studio → **Open** → `ThruOrder` 폴더 선택
2. Gradle Sync (처음엔 Gradle·AGP·Pleos SDK를 내려받느라 몇 분 걸립니다)
   - SDK Manager에 **Android 15 (API 35) SDK Platform**이 없으면 설치 안내가 뜹니다 → 설치
3. Pleos Connect 에뮬레이터(Pleos_Connect_v2.1.0)를 **cold boot**로 실행
4. 실행 대상에서 Pleos 에뮬레이터를 고르고 ▶ Run

### 현재 위치
따로 설정할 필요 없습니다. 에뮬레이터 기본 위치(판교 제2테크노밸리)를 그대로 씁니다.
다른 곳에서 시험하려면 Android Studio 하단 **Terminal**에서 `adb emu geo fix <경도> <위도>` (경도 먼저).

### 경로 위 DT 시연
1. (방법 A) Pleos 내비에서 목적지를 검색해 경로 안내 시작 → 스루오더 상단 카드가 "목적지 · 가는 길 DT N곳"으로 바뀜
2. (방법 B) 상단 **시연** → **목적지 없음** 칩을 눌러 잠실 → 광교 → 강남역 순으로 바꾸기 (내비 연결 시 내비에도 목적지가 잡힘)
3. 매장을 골라 주문하면 주문 상태에 "내비 경로에 매장을 넣었어요"가 뜨고, 내비 화면에 경유지가 보입니다

### 주행/정차 시연
- Virtual Console → Emulation Controls → **Gear Selection**을 D로 바꾸면 주행 화면으로 전환 (기어 연동이 되는 경우)
- 연동이 안 되면 상단 **시연** 패널의 **주행 / 정차** 사용

## 확인이 필요한 부분 (첫 실행 때 Logcat 태그 `ThruOrder`로 확인)
- `poiId`를 빈 값으로 보낸 `requestTrip`·`addWaypoint`를 내비가 받아주는지
- 기어 상태 권한(`CAR_POWERTRAIN`)이 허용되는지
- 빌드 오류가 나면 Build 창의 첫 번째 오류 메시지를 그대로 알려주세요
